# AI Code Review — xgb_einhers pipeline (Sprint 3.6)

**Date** : 2026-08-20
**Source** : revue externe (autre IA)
**Périmètre** : src/einherjar/research/xgb_einhers/ + tests/

## Executive Summary

Les résultats suspicieux (653 crypto, 0 forex, Sharpe 17.94, multi-actif 0/30)
sont dus à des **bugs logiques systémiques**, pas à la dynamique des marchés.

## P0 — Findings critiques

### Finding 1 : TP/SL hardcodés 2.5%/1.5% tuent forex/indices
- **Cause** : `backtester.py` lignes 270-277 utilise `tp_pct=0.025, sl_pct=0.015`
  quand `einher.tp_pct <= 0`. Sur forex, 6h = 0.05-0.20% de range, jamais hit TP.
- **Cause bis** : `runner.py` ligne 335 force `costs = max(load_costs, 0.0010)`
  (10 bps) sur tous les actifs. Forex spread = 1-3 bps → 10 bps = friction enorme.
- **Fix** : TP/SL dynamiques ATR-based + cost floor crypto-only.

### Finding 2 : Sharpe 17.94 + leakage val→holdout
- **Cause** : formule `sqrt(n_trades/years)` × returns quasi-constants (TP fixe) → Sharpe artificiel.
- **Cause bis** : `runner.py` lignes 386-392 slice val/holdout avec **bornes différentes** de `temporal_split` dans `data_loader.py` (lignes 208-226).
  - `temporal_split` : val = `[0.6*N+embargo : 0.6*N+embargo+0.2*N]`
  - `runner.py` : val = `[0.6*N+embargo : 0.8*N]`, holdout commence à `0.8*N+embargo`
  - Les barres `[0.8*N : 0.8*N+embargo]` ont été vues par le modèle mais sont dans le holdout.
- **Cause ter** : `admission.py` lignes 115-128 check holdout pour `n_trades >= 5` seulement,
  pas pour les performances. Une strat avec Sharpe 17 en val et -3 en holdout est admise.
- **Fix** : aligner slicing, vérifier holdout_metrics performance, cap std floor.

### Finding 3 : Multi-asset 0/30 (smoking gun)
- **Cause** : `runner.py` lignes 283-286 — `split_train_X = X_global_train` (213 cols),
  mais après `filter_sparse_patterns` + `apply_dedup`, `feature_names` a ~120 noms.
  XGBoost split sur index brut 0-212 mais path_extractor utilise feature_names 0-119.
  → AST invalide, 0 trades en val.
- **Cause bis** : `runner.py` ligne 228 — `valid_mask = np.ones(...)` en multi ignore les
  lignes avec `Y_dir == -100` qui polluent `_quick_importances`.
- **Fix** : slicer split_train_X/val_X/holdout_X avec keep_idx, valid_mask = Y_dir != -100.

## P1 — Findings importants

### Finding 5 : Two-sided p-value pénalise les perdants
- **Cause** : `backtester.py` lignes 235-241 utilise p-value bilatéral (`H0: μ=0`).
  Une strat perdante avec t=-3.5 a p≈0.00046, qui se retrouve en tête du BH ranking
  et vole le quota aux stratégies gagnantes.
- **Fix** : one-sided upper tail (`H0: μ ≤ 0`).

## P2 — Limitations design

### Finding 4 : Conditions AND-only
- **Cause** : `path_extractor.py` extrait 1 path par leaf, `condition_tree.py` les
  combine en AND uniquement. `ConditionNode` supporte OR/NOT/XOR mais le synthesizer
  ne merge pas les paths complémentaires en DNF.
- **Fix** : helper `merge_paths_or()` pour DNF.

### Finding 6 (mineur) : cmd_run scope overwrite
- **Cause** : `runner.py` ligne 465 force `scope="market" if multi else "asset"`,
  effaçant `scope="general"`.
- **Fix** : propager le vrai scope.
